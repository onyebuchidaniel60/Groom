# Groom — Design References, Mockups and Approval Record

**Status:** NOT STARTED — no visual direction approved.

This document is a mandatory gate. Final visual design may begin only after the core MVP journeys pass end-to-end tests on the deployed Preview and the operator reviews the evidence.

## Required process

1. Collect references from operator: URLs, screenshots, images or written direction.
2. If none supplied, coding agent presents 2–3 relevant reference candidates and waits for operator selection.
3. Create reference-informed mockups for:
   - Homepage
   - Owner dashboard / empty / populated
   - Experiment builder
   - Experiment detail and share link
   - Public experiment intro
   - Consent / age confirmation
   - Photo upload / invalid photo
   - Render progress / provider failure
   - Preview compare / ratings / favourite
   - Results locked (<5) and available (>=5)
   - Segment results suppressed (<10)
   - Pause/closed/expired/not-found/error states
4. Include desktop and mobile breakpoints.
5. Annotate reference source, borrowed attributes (hierarchy, density, typography mood, layout, interaction) and original/product-specific deviations.
6. Present mockups; capture feedback and revise.
7. Wait for explicit operator approval in writing. Silence or continued discussion is not approval.
8. Record approved version/date and links/assets below.
9. Implement only the approved direction; behavior/API/architecture changes need separate approval.
